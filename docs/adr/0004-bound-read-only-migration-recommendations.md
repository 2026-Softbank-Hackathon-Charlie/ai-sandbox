# 0004. 이전 추천은 기존 AI에 고정된 근거만 읽게 하고 서버 후보 안에서 선택한다

- 상태: 채택
- 날짜: 2026-11-08
- 관련 결정: 0001 서버 토폴로지 권한 보존, 0003 실제 AI·도구 Langfuse 기록

## 상황

개요 화면에서 요금·데이터 정책·환경 준비 상태를 함께 비교해 이전 후보를 짧게 보여줘야 한다. 사용자는 기존 AI 샌드박스에서 쓰던 AI의 재사용을 요구했다. 개요 방문마다 클러스터 생성과 DB 리허설을 실행하면 시간과 비용이 커진다. 추천이 실제 이전 승인이나 실행을 대신해서도 안 된다.

## 결정

`hopai recommend`는 기존 `llm.Agent`, Anthropic SDK client, `DefaultModel`, 기본 effort와 선택적 Langfuse 계측을 재사용한다. AI의 읽기 도구는 서버가 확인해 전달한 고정 스냅샷을 반환하는 `recommendation_snapshot` 하나다. kubeconfig, 운영 DB, Plan 생성·제출, 샌드박스 생성 및 이전 실행 도구는 제공하지 않는다.

입력은 최대 64KiB이며 snapshot ID, 생성·만료 시각과 최대 16개 후보를 갖는다. 후보의 앱·원본·대상·허용 action·이유·출처·미확인 항목·추정 절감액은 서버 소유다. 도구를 실제로 읽어야 결과를 인정한다. AI는 후보의 우선순위, 허용된 `move/stay/insufficient`, 기존 이유 중 최대 두 개만 선택한다. 새 수치·가격·환경·출처를 출력할 수 없다. 최대 네 개 결과의 ID 중복, 다른 스냅샷, 허용되지 않은 동작, 새 이유와 알 수 없는 JSON 필드는 거부한다. 플랫폼도 원래 사실과 대조해야 한다.

출력 token은 응답당 1500, tool runner는 최대 3회, SDK 재시도와 검사 재시도는 0회, HTTP 호출당 30초·전체 AI 작업 60초로 제한한다. 공유 task에 선택적 요청 옵션만 추가하여 기존 계획·진단 작업의 예산은 바꾸지 않는다. 실제 마지막 API 응답의 model ID와 플랫폼 explain session ID를 전달한다. schema는 Claude가 지원하는 JSON Schema만 쓰며 배열 상한은 Go에서 별도로 강제한다.

CLI는 기존 플랫폼 agent bearer 인증과 일회용 nonce로 지정된 결과 endpoint 하나에만 callback한다. nonce, bearer token과 provider key는 AI·tool·세션 입력과 출력 로그에 넣지 않는다. URL은 운영자 설정만 사용하고 redirect를 따르지 않으며 callback은 5초·32KiB로 제한한다. 실패는 고정 error code로 보고하고 upstream 오류 원문은 전달하지 않는다. 입력·model·도구 호출·판단은 기존 agentlog와 선택적 Langfuse 경로로 기록한다.

호출 여부, 사용자 권한, 전체 추천 묶음의 최소 갱신 간격·단일 실행, 재시작 시 비용 한도, nonce 검증과 증거·대상 준비 상태 재검사는 플랫폼 소유다. 프론트엔드의 새로고침 버튼이나 AI 판단이 이 경계를 우회하지 않는다. 배포 템플릿의 추천 mode는 기존 Anthropic key와 agent token만 읽어야 하며 kubeconfig는 읽지 않는다.

## 검토한 대안

- 규칙만으로 추천하면 요청한 기존 AI 재사용을 충족하지 못한다.
- 기존 `hopai run` 전체 실행은 추천과 무관한 리허설 자원을 만들고 DB·클러스터 경계를 넓히므로 제외했다.
- 자유로운 AI 이유 문구는 근거 없는 절감액·요금 변경·데이터 정책 주장을 만들 수 있어 기존 근거 선택으로 제한했다.
- 플랫폼 API에 provider key를 새로 공급하는 대신 기존 AI runner의 자격증명 경계를 재사용한다.

## 결과

신규 키·IAM·상시 수집·유료 평가자를 추가하지 않는다. 반도체 시장 전망과 클라우드 청구액은 별도 근거이며, 온프레미스 운영비·약정·egress가 없으면 실제 절감이라고 확정하지 않는다. 추천 자체는 어떤 실행도 하지 않으며 이후 사용자가 이전 화면에서 정상 계획·검사·승인 절차를 거친다.

단위·HTTP fixture 검사는 경계와 예산을 검증할 뿐 실제 모델 품질·운영 요금·운영 배포 성공을 증명하지 않는다. 이 변경의 검증 중 실제 모델 호출과 운영 데이터·키 조회는 실행하지 않는다. 기존 이미지에 이 명령이 없거나 플랫폼 템플릿이 추천 mode를 지원하지 않으면 플랫폼은 미연결로 표시해야 한다.
