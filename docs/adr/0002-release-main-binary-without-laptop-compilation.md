# 0002. 검증된 main의 Linux 바이너리를 수동 CI 산출물로 발행한다

- 상태: 채택
- 날짜: 2026-11-07

## 상황

작업 브랜치 커밋이 squash merge 뒤 삭제되어 플랫폼·엔진 모듈을 다시 받을 수 없고 main CI가 실패했다. 운영 AI 이미지도 이전 버전이다. 운영자 노트북의 디스크 여유가 부족해 로컬 전체 Go 컴파일은 안전하게 완료하기 어렵다. AI 저장소에는 ECR 발행 역할이 구성되어 있지 않다.

## 결정

모듈은 정식 main에서 도달 가능한 커밋으로 고정한다. 기존 CI의 vet·포맷·전체 테스트를 통과한 수동 main 실행에서만 Linux amd64 정적 바이너리를 만든다. 산출물에는 원본 커밋, Go build info와 SHA256을 포함하고 하루 동안 보관한다. CI에 AWS 자격 증명을 추가하지 않는다.

운영자는 검증된 바이너리로 기존 digest가 고정된 AI 이미지의 실행 파일을 교체한 새 이미지를 만들고, 새 digest를 GitOps에 고정한다. 기존 도구와 실행 환경은 유지한다. 이미지 구성·원본 바이너리 checksum·내장 모듈 버전과 적용 후 Pod 또는 다음 Job 템플릿의 이미지를 검증한다. 완료된 Job은 이력이며 새 이미지를 시험하기 위해 운영 AI 작업을 다시 실행하지 않는다.

## 검토한 대안

- 노트북에서 재컴파일: 디스크 부족을 반복하므로 제외한다.
- 실패한 main CI를 무시해 발행: 검증 단계가 생략되므로 제외한다.
- CI에 새 AWS 역할·키 추가: 권한 변경 범위를 늘리므로 이번 작업에서 제외한다.

## 결과

이 워크플로는 바이너리를 발행하고 클러스터를 바꾸지 않는다. registry push·GitOps 변경·재시작은 사용자에게 승인된 별도 운영 작업이다. source checksum은 바이너리와의 연결 근거이며 실제 LLM 호출·운영 데이터 이전 성공의 증거가 아니다.
